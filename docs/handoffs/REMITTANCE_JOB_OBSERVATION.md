# Durable remittance job observation

A retained physical capture was queued, claimed once by a healthy worker, and durably acknowledged as review 96.9 seconds after enqueue. The previous client observer stopped after90seconds. That cutoff lost a legitimate late result; the worker job was not orphaned. Reopening historical evidence also left a Checking payment history label because the historical-save path intentionally does not rewrite the saved attempt.

The client now limits the foreground spinner to45seconds and continues observing the SAME job in a nonspinning saved-progress state. A result automatically enters the existing review handler. Observation has a32minute ceiling around the database's existing30minute absolute job deadline. Consecutive connection failures, unreadable terminal results and authentication failures become actionable errors. Auth, response-body and saved-image/metadata waits are bounded; recent-job refresh cannot overlap itself. Lost enqueue acknowledgements are resolved by status lookup and any retry uses the same idempotent job identity.

The foreground watchdog cannot invalidate an active observer or a terminal/newer view when a suspended PWA resumes with overdue timers. A review-preparation error is distinguished from OCR/job failure. Normalization, guided camera/no mandatory crop, OCR recognition/authority, money, matching, financial eligibility/application, schema, leases, recovery/reaper, duplicate and split safeguards and mandatory email approval are unchanged.

The new regression uses measured timing only, never invoice/amount/image truth. It executes the actual observer, background-status JSX and watchdog: finite spinner,97second review, suspended-PWA timers, same-ID reconnect/recovery, worker offline/stalled/failure, cancellation, lost acknowledgement, missing terminal result and hung payment-history response body. The full retained-image library and release gates remain required. No physical acceptance is inferred from automated replay and no real payment is applied.
